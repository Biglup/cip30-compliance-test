14. CIP-209 (Dijkstra connector extension)

            
Test the draft CIP-30 extension CIP-209: getBalances, signSubTxs, balanceAndSignTx and the amended signTx. The wallet must list { cip: 209 } in supportedExtensions and expose api.cip209.

            

            

                
                
Applies to the two cards that build with the transaction builder (signSubTxs and the wrap card). Requires the endpoint's protocol 12 parameters. Leave unchecked to test signing only with protocol 12 candidate parameters. Custom devnets use the slot timing entered in section 13.

            

            

                
                
balanceAndSignTx lets the WALLET decide whether to submit, and CIP-209 gives the dApp no flag to prevent it. Every balanceAndSignTx call in this section, including the raw call, stays disabled until this is checked.

            

            

                
getBalances

                
Read the wallet's UTxOs and the balance of each registered reward account in one call. Pagination applies to the UTxOs only; leave both fields blank to omit it.

                

                    

                    

                

                

                    
                

                

            

            

                
signSubTxs over built intents

                
Build intents funded by this wallet: each spends one of its ADA-only UTxOs, pays the recipient, returns the change and requires the batcher's top-level guard. Sign them as a participant, then copy the signed subtransactions to the batcher's session and paste them into the wrap card there.

                

                

                

                

                

                    
                    
                

                

                    
                    
                    
                

                

                

                

            

            

                
Wrap imported subtransactions (two-wallet flow)

                
Paste subtransactions signed by another wallet whose batcher is this wallet. The top-level transaction is funded by this wallet, carries them unchanged and adds this wallet's payment-key guard, so the wallet's review shows a counterparty's subtransaction. It is signed with plain signTx, which must refuse with TxSignError 7 when an imported subtransaction is not fully witnessed. Every input must already exist on chain: an imported subtransaction cannot spend an output of another one.

                

                

                    
                    
                    
                

                

                

            

            

                
balanceAndSignTx

                
THIS CALL MAY SUBMIT A REAL TRANSACTION. The wallet balances, signs and, when the result is complete, may submit without asking this page again. To hold a complete transaction back, the CIP directs dApps to plain signTx instead.

                
Send an incomplete transaction with no inputs, a placeholder fee of 0 and no change. The subtransaction forms read the textarea of the wrap card.

                

                    
                    
                

                

                

                

                    
                    
                

                

                

                

            

            

                
Raw calls

                
Call a method with exactly the arguments given, as a JSON array, and see the raw result or the raw error object. Examples: [] or [{"page":0,"limit":10}] for getBalances, [["83a3..."],"full"] for signSubTxs, ["84a3..."] for balanceAndSignTx, ["84a3...",true] for signTx.

Each fills the form; the expected outcome is APIError InvalidRequest (-1).
